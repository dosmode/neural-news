# Implementation Plan: Inter-Keyword Cross Links

**Branch**: `016-inter-keyword-links` | **Date**: 2026-06-09 | **Spec**: [spec.md](./spec.md)

**Input**: Feature specification from `specs/016-inter-keyword-links/spec.md`

## Summary

Add **cross-links** between related keyword nodes in the force-directed graph (features 014/015) so it reads as a network, not just a hierarchy tree. Two live nodes get a connecting line when they're related per the existing `KEYWORD_SUGGESTIONS_MAP` (bidirectional union), even if they aren't in a parent-child relationship. Cross-links are **derived** (not stored) from the live node set, deduped against hierarchy links, capped for density, and merged into the single link array that already drives the simulation, rendering, and hover highlight — so physics and interactions work for free. Cross-links are styled distinctly (dashed, dimmer) from hierarchy links. No new files or dependencies.

## Implementation Phases

### Phase 1: Data Layer (graphTree)
- **1.1** Add `type?: 'hierarchy' | 'cross'` to `GraphLink`; add `MAX_CROSS_LINKS`.
- **1.2** Implement `areRelated(a, b)` — bidirectional union over `KEYWORD_SUGGESTIONS_MAP` (false for self).
- **1.3** Implement `computeCrossLinks(nodes, hierarchyLinks)` — unordered pairs, dedup vs hierarchy pair keys (handle string|object endpoints), cap at `MAX_CROSS_LINKS`.
- **1.4** Tag links created in `buildOverview` with `type: 'hierarchy'`.
- **1.5** Tests in `tests/utils/graphTree.test.ts`.

### Phase 2: User Story 1 — Related Keywords Connected (P1)
- **2.1** In `ForceGraphPanel.tsx`, tag hierarchy links created on expand with `type: 'hierarchy'`.
- **2.2** Add `crossLinks = useMemo(computeCrossLinks(liveNodes, liveLinks), [liveNodes, liveLinks])` and `allLinks = useMemo([...liveLinks, ...crossLinks], [liveLinks, crossLinks])`.
- **2.3** Render `allLinks` (was `liveLinks`) in the SVG link loop.

### Phase 3: User Story 2 — Cross Links Behave Like Real Connections (P2)
- **3.1** Pass `allLinks` to `useForceSimulation({ links: allLinks })` so cross-links exert attraction (FR-006).
- **3.2** Compute hover `neighborIds` over `allLinks` so cross neighbors highlight (FR-007).

### Phase 4: User Story 3 — Visual Distinction (P3)
- **4.1** In `GraphLinkView.tsx`, branch on `link.type`: cross = dashed, muted purple, lower opacity, thinner; hierarchy = current style.

### Phase 5: Validation
- **5.1** `npx tsc --noEmit` clean.
- **5.2** `npm test` green (new util tests + existing suite).
- **5.3** `npm run dev` manual: cross links appear for related non-parent nodes, none for unrelated, hover lights cross neighbors, collapse removes cross links, cross vs hierarchy visually distinct.

## Key Design Decisions

| Decision | Choice | Reference |
|----------|--------|-----------|
| Relation rule | adjacency-map bidirectional union | research.md D-001 |
| Cross-links derived, not stored | useMemo from live nodes | research.md D-002 |
| Dedup | unordered pair key vs hierarchy | research.md D-003 |
| Density | `MAX_CROSS_LINKS` cap + lighter style | research.md D-004 |
| Visual distinction | dashed muted-purple cross vs solid hierarchy | research.md D-005 |
| Physics/hover | merge into single `allLinks` | research.md D-006 |
