# Feature Specification: Obsidian-Style Force-Directed Graph View

**Feature Branch**: `014-force-directed-graph`

**Created**: 2026-06-09

**Status**: Draft

**Input**: User description: 옵시디언(Obsidian)의 그래프 뷰처럼 하나의 중심 키워드에서 연관 키워드가 방사형으로 펼쳐지는 노드-링크 네트워크(force-directed graph)를 구현. 노드 클릭 시 자식 노드가 스프링 애니메이션으로 펼쳐지고 다시 클릭하면 접힘. 노드를 드래그 앤 드롭으로 이동 가능. 노드에 마우스를 올리면 직접 연결된 링크/노드만 하이라이트.

## User Scenarios & Testing *(mandatory)*

### User Story 1 - Click to Expand/Collapse Related Keywords (Priority: P1)

사용자가 그래프 중앙의 중심 키워드 노드를 본다. 노드를 클릭하면 숨겨져 있던 연관 키워드 자식 노드들이 스프링(탄성) 애니메이션과 함께 방사형으로 자연스럽게 펼쳐진다. 같은 노드를 다시 클릭하면 자식 노드들이 다시 중심으로 접혀 사라진다. 펼쳐진 자식 노드도 클릭하면 그 노드의 손자 노드들이 다시 펼쳐져, 옵시디언처럼 계속해서 네트워크가 확장된다.

**Why this priority**: 이것이 옵시디언 그래프 뷰의 핵심 경험이다. "중심에서 펼쳐지고 접히는" 탄성 있는 인터랙션이 없으면 단순한 정적 그래프에 불과하다. 이 한 가지만 구현해도 독립적으로 가치 있는 MVP가 된다.

**Independent Test**: 중심 노드 "인공지능"을 클릭하면 "머신러닝", "딥러닝" 같은 자식 노드가 스프링 애니메이션으로 펼쳐지고, 다시 클릭하면 접히는 것을 확인할 수 있다. "딥러닝"을 클릭하면 "CNN", "RNN"이 다시 펼쳐진다.

**Acceptance Scenarios**:

1. **Given** 중심 노드만 표시된 초기 상태에서, **When** 사용자가 중심 노드를 클릭하면, **Then** 연관 자식 노드들이 스프링 애니메이션과 함께 중심에서 방사형으로 펼쳐지고 노드 사이에 연결선이 그려진다.
2. **Given** 자식 노드가 펼쳐진 상태에서, **When** 사용자가 같은 중심 노드를 다시 클릭하면, **Then** 자식 노드들이 중심으로 부드럽게 접혀 사라지고 연결선도 함께 사라진다.
3. **Given** 1차 자식 노드가 펼쳐진 상태에서, **When** 사용자가 자식 노드 하나를 클릭하면, **Then** 그 노드의 손자 노드들이 펼쳐져 네트워크가 한 단계 더 확장된다.
4. **Given** 노드들이 펼쳐진 상태에서, **When** 아무 조작도 하지 않으면, **Then** 노드들은 물리 시뮬레이션에 따라 서로 겹치지 않고 안정적인 위치로 자리잡는다.

---

### User Story 2 - Drag Nodes to Reposition (Priority: P2)

사용자가 그래프의 어떤 노드든 마우스로 잡아 끌어서(드래그 앤 드롭) 원하는 위치로 옮길 수 있다. 노드를 끄는 동안 연결된 다른 노드들도 물리적으로 함께 따라 움직이며, 놓으면 그 위치에 자연스럽게 고정되거나 시뮬레이션에 다시 통합된다.

**Why this priority**: 사용자가 복잡해진 그래프를 직접 정리하고 탐색할 수 있게 해주는 핵심 조작이다. 펼치기/접기(P1) 다음으로 중요하다.

**Independent Test**: 아무 노드나 마우스로 잡고 화면의 다른 위치로 끌어다 놓으면, 노드가 마우스를 따라 이동하고 연결된 노드들이 자연스럽게 반응하는 것을 확인할 수 있다.

**Acceptance Scenarios**:

1. **Given** 여러 노드가 펼쳐진 상태에서, **When** 사용자가 한 노드를 마우스로 누른 채 움직이면, **Then** 그 노드가 마우스 포인터를 따라 이동한다.
2. **Given** 노드를 드래그하는 동안, **When** 노드가 이동하면, **Then** 그 노드에 연결된 다른 노드와 링크가 물리적으로 자연스럽게 반응한다.
3. **Given** 노드를 드래그 중일 때, **When** 사용자가 마우스를 놓으면, **Then** 노드가 놓인 위치 기준으로 안정화된다.

---

### User Story 3 - Hover to Highlight Connected Neighbors (Priority: P3)

사용자가 특정 노드에 마우스를 올리면(hover), 그 노드와 직접 연결된 링크 및 이웃 노드만 선명하게 강조되고, 나머지 관련 없는 노드와 링크는 흐릿하게 처리된다. 마우스를 떼면 전체 그래프가 원래 밝기로 돌아온다.

**Why this priority**: 그래프가 커졌을 때 특정 키워드의 관계를 한눈에 파악하게 해주는 탐색 보조 기능이다. 핵심 조작은 아니지만 옵시디언 경험의 완성도를 높인다.

**Independent Test**: 노드가 여러 개 펼쳐진 상태에서 한 노드에 마우스를 올리면 그 노드와 직접 연결된 것들만 밝게, 나머지는 어둡게 처리되는 것을 확인할 수 있다.

**Acceptance Scenarios**:

1. **Given** 여러 노드가 펼쳐진 상태에서, **When** 사용자가 한 노드에 마우스를 올리면, **Then** 해당 노드와 직접 연결된 노드/링크만 강조되고 나머지는 흐려진다.
2. **Given** 한 노드가 하이라이트된 상태에서, **When** 사용자가 마우스를 그 노드에서 떼면, **Then** 모든 노드와 링크가 원래의 균일한 밝기로 복원된다.

---

### Edge Cases

- 노드가 매우 많이 펼쳐졌을 때(예: 50개 이상) 그래프 성능과 가독성은 어떻게 유지되는가?
- 부모 노드를 접을 때, 그 아래에 펼쳐져 있던 손자/증손자 노드들은 모두 함께 접히는가?
- 드래그 중인 노드를 클릭으로 간주하지 않도록 클릭과 드래그를 어떻게 구분하는가?
- 연관 키워드가 없는 노드(말단 노드)를 클릭하면 어떤 피드백을 주는가?
- 좁은 화면(모바일)에서 방사형 펼침이 화면 밖으로 나가는 경우 어떻게 처리하는가?

## Requirements *(mandatory)*

### Functional Requirements

- **FR-001**: 시스템은 그래프 영역 중앙에 중심 키워드 노드를 렌더링해야 한다.
- **FR-002**: 노드는 물리 기반 시뮬레이션(force-directed)에 따라 서로 밀어내고 링크로 당겨져 자동으로 배치되어야 한다.
- **FR-003**: 사용자가 노드를 클릭하면 그 노드의 연관(자식) 키워드 노드들이 스프링/탄성 애니메이션과 함께 펼쳐져야 한다.
- **FR-004**: 이미 펼쳐진 노드를 다시 클릭하면 그 자식 노드들(및 그 하위 전체)이 접혀 사라져야 한다.
- **FR-005**: 노드는 여러 단계로 계속 확장 가능해야 한다(중심 → 자식 → 손자 → ...).
- **FR-006**: 노드와 노드 사이의 관계는 링크(선)로 시각적으로 표현되어야 한다.
- **FR-007**: 사용자는 어떤 노드든 마우스로 드래그하여 위치를 이동할 수 있어야 한다.
- **FR-008**: 노드를 드래그하는 동안 연결된 노드와 링크가 물리적으로 자연스럽게 반응해야 한다.
- **FR-009**: 사용자가 노드에 마우스를 올리면 직접 연결된 노드/링크만 강조되고 나머지는 흐려져야 한다.
- **FR-010**: 마우스를 떼면 하이라이트 상태가 해제되고 그래프가 원래 상태로 복원되어야 한다.
- **FR-011**: 각 노드의 펼침/접힘(expand/collapse) 상태가 관리되고 시각적으로 구분되어야 한다(예: 접힌 자식이 있는 노드 표시).
- **FR-012**: 클릭(펼치기/접기)과 드래그(이동)는 명확히 구분되어 서로 오작동을 일으키지 않아야 한다.
- **FR-013**: 그래프는 기존 키워드 기반 뉴스 필터링과 연동되어, 펼쳐져 활성화된 키워드가 뉴스 피드에 반영되어야 한다.

### Key Entities

- **GraphNode**: 그래프의 점. 속성: id, label(키워드 이름), 깊이/레벨, 부모 노드 참조, 펼침 상태(expanded/collapsed), 자식 보유 여부, 화면 좌표(x, y), 고정 여부(드래그로 고정됐는지)
- **GraphLink**: 두 노드를 잇는 선. 속성: 출발 노드(source), 도착 노드(target), 강조 상태
- **GraphState**: 전체 그래프의 상태. 속성: 표시 중인 노드 집합, 표시 중인 링크 집합, 현재 hover된 노드, 현재 드래그 중인 노드

## Success Criteria *(mandatory)*

### Measurable Outcomes

- **SC-001**: 노드를 클릭하면 0.5초 이내에 자식 노드 펼침 애니메이션이 시작된다.
- **SC-002**: 펼침/접힘 및 드래그 애니메이션이 최소 50개 노드까지 끊김 없이(초당 약 60프레임 수준) 부드럽게 동작한다.
- **SC-003**: 사용자가 노드를 드래그할 때 포인터와 노드 사이의 시각적 지연이 느껴지지 않는다.
- **SC-004**: 노드에 마우스를 올린 직후 0.2초 이내에 이웃 하이라이트가 적용된다.
- **SC-005**: 최소 3단계 깊이(중심 → 자식 → 손자)까지 펼침이 정상 동작한다.
- **SC-006**: 사용자 테스트에서 80% 이상이 "옵시디언 그래프 뷰와 유사한 탐험 경험"이라고 평가한다.
- **SC-007**: 기존 키워드 기반 뉴스 필터링이 새 그래프에서도 회귀 없이 동일하게 동작한다.

## Assumptions

- 이 기능은 기존의 단순 부유(floating) 방식 키워드 패널을 진짜 물리 기반 force-directed 그래프로 대체한다.
- 연관 키워드 데이터(어떤 키워드가 어떤 자식 키워드로 펼쳐지는지)는 기존에 구축된 키워드 추천 데이터를 재사용한다.
- 노드의 시각적 스타일(네온/다크 테마)은 기존 앱의 디자인 언어를 따른다.
- 초기 표시되는 중심 노드는 사용자가 추가했거나 트렌딩으로 선정된 대표 키워드다.
- 데스크톱 환경을 우선으로 하며, 모바일에서는 동작은 하되 터치 제스처 최적화는 이번 범위 밖이다.
- 활성 키워드 수에는 기존과 동일한 상한이 적용된다.
