## User Scenarios & Testing *(mandatory)*

### User Story 1 - Add Keyword and Watch Suggestions Float In (Priority: P1)

사용자가 왼쪽 패널에 키워드를 입력하면, 그 키워드가 패널 안에서 둥둥 떠다니는 노드로 나타난다. 동시에 AI가 해당 키워드에서 파생되는 연관 키워드 후보들을 자동으로 생성해 반투명한 "추천 노드"로 주변에 떠오른다.

**Why this priority**: 이것이 기능의 핵심 경험이다. 사용자가 처음으로 키워드를 추가할 때 즉각적인 "파생 확장" 피드백이 있어야 Obsidian 스타일의 탐험 느낌이 형성된다.

**Independent Test**: 패널에 "인공지능" 키워드를 추가했을 때, 키워드 노드가 패널 안에 부유하며 "머신러닝", "딥러닝", "자연어처리" 등의 추천 노드들이 주변에 자동으로 나타남을 확인할 수 있다.

**Acceptance Scenarios**:

1. **Given** 빈 패널이 있을 때, **When** 사용자가 키워드 "AI"를 추가하면, **Then** "AI" 노드가 패널 안에 부유하는 형태로 나타나고, 3~6개의 연관 추천 키워드 노드들이 주변에 반투명하게 표시된다.
2. **Given** 키워드 노드가 패널 안에 있을 때, **When** 아무 조작도 하지 않아도, **Then** 노드들은 부드럽게 패널 안에서 떠다니는 애니메이션을 유지한다.
3. **Given** 추천 노드가 표시되어 있을 때, **When** 사용자가 추천 노드를 클릭하면, **Then** 해당 추천 키워드가 정식 키워드로 확정되어 노드가 불투명해지고, 그 키워드에서 다시 새로운 추천 노드들이 파생된다.

---

### User Story 2 - Obsidian-Style Cascading Derivation (Priority: P2)

사용자가 추천 키워드를 채택할 때마다, 그 키워드에서 다시 새로운 연관 키워드들이 파생되어 나온다. 이 과정이 반복되면서 키워드 그래프가 Obsidian의 노트 그래프처럼 점점 확장되어 나가는 탐험 경험을 제공한다.

**Why this priority**: 단순한 키워드 추가를 넘어서 "발견의 여정" 느낌을 주는 것이 이 기능의 차별화 포인트다.

**Independent Test**: 키워드를 하나 추가하고, 나타난 추천 중 하나를 채택하면, 채택된 노드에서 또 새로운 추천들이 파생되어 그래프가 트리처럼 확장되는 것을 확인할 수 있다.

**Acceptance Scenarios**:

1. **Given** 2개 이상의 정식 키워드가 있을 때, **When** 사용자가 세 번째 키워드를 추천에서 채택하면, **Then** 세 번째 노드에서 새로운 추천 노드들이 파생되어 기존 그래프에 추가된다.
2. **Given** 키워드 그래프가 확장된 상태일 때, **When** 사용자가 기존 정식 키워드 노드를 클릭하면, **Then** 그 노드의 추천 키워드들이 펼쳐지거나 접힌다(토글).
3. **Given** 패널 안에 노드들이 많아진 상태일 때, **When** 새로운 키워드가 추가되면, **Then** 새 노드는 기존 노드들과 충돌하지 않는 위치에 자연스럽게 배치된다.

---

### User Story 3 - Remove Keyword and Collapse Derived Graph (Priority: P3)

사용자가 특정 키워드를 제거하면, 그 키워드에서 파생된 추천 노드들도 함께 사라지거나 별도의 독립 노드로 전환된다.

**Why this priority**: 그래프가 커졌을 때 사용자가 탐색을 되돌리거나 정리할 수 있어야 한다.

**Independent Test**: 키워드를 추가하고 2~3개의 파생 노드를 채택한 후, 원래 키워드를 제거하면 연결된 파생 노드들의 처리 방식(삭제 또는 독립 전환)을 확인할 수 있다.

**Acceptance Scenarios**:

1. **Given** 키워드 A에서 파생된 추천 B, C가 있을 때, **When** 사용자가 키워드 A를 제거하면, **Then** 추천 B, C도 함께 패널에서 사라진다.
2. **Given** 추천 B가 이미 정식 채택된 키워드인 경우, **When** 원래 키워드 A를 제거하면, **Then** 채택된 B는 독립 루트 노드로 남아 계속 표시된다.

---

### Edge Cases

- 패널 공간이 가득 찼을 때 추가 노드 배치는 어떻게 처리하는가?
- AI 추천 생성이 지연되거나 실패했을 때 사용자에게 어떻게 피드백을 주는가?
- 최대 키워드 수에 도달했을 때 추천 노드의 채택을 막을 것인가?
- 동일한 추천이 여러 키워드에서 파생될 때 중복 노드를 어떻게 처리하는가?

## Requirements *(mandatory)*

### Functional Requirements

- **FR-001**: 시스템은 사용자가 키워드를 추가할 수 있어야 한다 (텍스트 입력 + 엔터/버튼 클릭).
- **FR-002**: 추가된 모든 키워드 노드는 패널 안에서 부드럽게 부유하는 애니메이션을 가져야 한다.
- **FR-003**: 키워드가 추가되면 시스템은 해당 키워드에서 파생된 연관 추천 키워드 3~6개를 자동으로 생성해야 한다.
- **FR-004**: 추천 키워드는 시각적으로 정식 키워드와 구별되어야 한다 (반투명, 다른 색상, 점선 테두리 등).
- **FR-005**: 추천 키워드와 그것을 발생시킨 정식 키워드 사이에는 연결선이 표시되어야 한다.
- **FR-006**: 사용자가 추천 노드를 클릭하면 정식 키워드로 채택되고, 새로운 추천들이 파생되어야 한다.
- **FR-007**: 사용자가 추천 노드를 무시(거절)할 수 있어야 한다 (닫기 버튼 또는 다른 제스처).
- **FR-008**: 사용자가 정식 키워드를 제거할 수 있어야 한다.
- **FR-009**: 정식 키워드 노드를 클릭하면 그 노드의 추천들이 펼쳐지거나 접힌다.
- **FR-010**: 시스템은 최대 키워드 수(정식 채택된 것 기준) 제한을 적용해야 한다.
- **FR-011**: 정식 키워드들은 기존 뉴스 필터링 기능과 연동되어 뉴스 피드에 반영되어야 한다.

### Key Entities

- **KeywordNode**: 사용자가 추가하거나 채택한 정식 키워드. 속성: id, label, isActive, position(x,y), parentId(파생 원천 노드, 없으면 루트)
- **SuggestionNode**: AI가 자동 생성한 추천 키워드. 속성: id, label, sourceKeywordId, isVisible
- **GraphEdge**: 노드 간 연결선. 속성: id, sourceId, targetId, type(keyword-to-suggestion | keyword-to-keyword)

## Success Criteria *(mandatory)*

### Measurable Outcomes

- **SC-001**: 사용자가 키워드를 추가했을 때 2초 이내에 추천 노드들이 화면에 나타난다.
- **SC-002**: 추천 노드를 채택하는 인터랙션(클릭 → 새 추천 파생)이 1.5초 이내에 완료된다.
- **SC-003**: 최소 3단계 깊이의 키워드 파생(루트 → 1차 추천 채택 → 2차 추천 채택 → 3차 추천 등장)이 지원된다.
- **SC-004**: 모든 노드가 패널 경계를 벗어나지 않고 부유한다.
- **SC-005**: 사용자 테스트에서 "Obsidian 그래프 탐험" 경험과 유사하다고 느끼는 비율이 80% 이상이다.
- **SC-006**: 기존 키워드 기반 뉴스 필터링 기능이 새 UI에서도 동일하게 동작한다(회귀 없음).

## Assumptions

- 연관 추천 키워드 생성은 클라이언트 측 로직 또는 기존 GDELT API 데이터를 활용하여 구현 가능하다고 가정한다 (별도 AI 추천 API 없이도 구현 가능).
- 부유 애니메이션은 물리 시뮬레이션 또는 CSS/JS 기반 단순 이동으로 구현하며, 성능 저하 없이 동작한다고 가정한다.
- 현재 NeuralPanel이 담당하는 키워드 관리 및 필터링 연동 로직은 신규 컴포넌트로 그대로 이전된다.
- 기존 `useStore`의 `keywords`, `activeKeywords`, `addKeyword`, `removeKeyword`, `toggleKeyword` 등의 상태 관리는 유지하고 UI 레이어만 교체한다.
- 모바일 반응형 지원은 이번 피처 범위 밖이다 (데스크톱 우선).
