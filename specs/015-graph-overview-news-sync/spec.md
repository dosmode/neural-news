# Feature Specification: Graph Overview, Natural UX & Clicked-Node Article Sync

**Feature Branch**: `015-graph-overview-news-sync`

**Created**: 2026-06-09

**Status**: Draft

**Input**: User description: "그래프가 이미 전체적으로 보인상태였으면 좋겠고 UXUI가 너무 자연스럽지못해 그리고 클릭한 연관 노드들이 기사 결과로 나오지 않고 있어"

## Overview

키워드 그래프(좌측 패널)의 세 가지 개선 요청:
1. 처음부터 그래프 전체 구조가 펼쳐져 보이기 (옵시디언 전체 그래프 뷰처럼)
2. 인터랙션/애니메이션이 더 자연스럽게
3. **[버그]** 클릭해서 선택한 연관 노드가 기사 결과(뉴스 피드)에 반영되지 않는 문제 수정

## User Scenarios & Testing *(mandatory)*

### User Story 1 - Clicked Related Nodes Drive Article Results (Priority: P1) 🐞 Fix

사용자가 그래프에서 연관 키워드 노드를 클릭해 선택하면, 그 키워드가 즉시 기사 필터에 반영되어 해당 키워드와 관련된 기사들이 오른쪽 결과 영역에 나타나야 한다. 현재는 연관 노드를 클릭해도 기사 결과가 바뀌지 않는다.

**Why this priority**: 핵심 기능이 깨져 있다. 그래프 탐색의 목적은 키워드를 골라 관련 뉴스를 보는 것인데, 클릭이 결과에 반영되지 않으면 그래프가 뉴스 피드와 단절된 장식에 그친다. 가장 먼저 고쳐야 한다.

**Independent Test**: 그래프에서 임의의 연관 노드(예: 루트 "AI"에서 파생된 "OpenAI")를 클릭해 선택하면, 오른쪽 기사 영역에 "OpenAI" 관련 기사가 새로 나타나는 것을 확인할 수 있다.

**Acceptance Scenarios**:

1. **Given** 루트 키워드들이 표시된 상태에서, **When** 사용자가 한 연관 노드를 클릭해 선택하면, **Then** 그 키워드가 활성 필터에 추가되고 관련 기사가 결과 영역에 반영된다.
2. **Given** 여러 노드가 선택된 상태에서, **When** 사용자가 선택을 해제(또는 노드를 접거나 제거)하면, **Then** 해당 키워드가 필터에서 빠지고 기사 결과가 그에 맞게 갱신된다.
3. **Given** 깊은 단계(2~3차)의 연관 노드를 선택했을 때, **When** 그 노드가 활성화되면, **Then** 깊이에 관계없이 해당 키워드가 기사 결과에 반영된다 (루트만 우선되어 잘려나가지 않는다).
4. **Given** 활성 키워드 수가 많아질 때, **When** 시스템이 기사를 가져오면, **Then** 최근에 선택한 키워드가 우선적으로 결과에 반영된다.

### User Story 2 - Graph Shows Full Overview by Default (Priority: P2)

사용자가 화면을 처음 열었을 때, 중심 노드만 덩그러니 있는 게 아니라 주요 키워드와 그에 연관된 1차 노드들이 이미 펼쳐져 그래프의 전체적인 구조가 한눈에 보여야 한다. 옵시디언 그래프 뷰를 처음 열었을 때처럼 "관계망"이 즉시 드러나는 느낌.

**Why this priority**: 빈 중심 노드에서 사용자가 일일이 클릭해야만 구조가 보이면 탐색 시작이 막막하다. 처음부터 전체 그림을 보여주면 탐색 동기와 방향이 생긴다.

**Independent Test**: 페이지를 새로 열면(또는 새로고침하면) 루트 키워드들과 각각의 1차 연관 노드들이 이미 펼쳐진 상태로, 패널 안에 고르게 퍼진 네트워크가 보이는 것을 확인할 수 있다.

**Acceptance Scenarios**:

1. **Given** 첫 방문/새로고침 상태에서, **When** 그래프가 로드되면, **Then** 루트 키워드 + 1차 연관 노드들이 이미 펼쳐져 전체 구조가 보인다.
2. **Given** 전체 펼쳐진 초기 상태에서, **When** 사용자가 노드를 클릭하면, **Then** 펼치기/접기 토글이 정상 동작한다 (초기 펼침이 이후 조작을 방해하지 않는다).
3. **Given** 초기 그래프가 펼쳐진 상태에서, **When** 노드들이 배치되면, **Then** 노드들이 한곳에 뭉치지 않고 패널 영역에 고르게 분포한다.

### User Story 3 - Natural, Polished Interactions (Priority: P3)

그래프의 등장·펼침·접힘·드래그·호버 등 모든 인터랙션이 매끄럽고 자연스럽게 느껴져야 한다. 노드가 갑자기 튀거나, 겹치거나, 끊기듯 움직이거나, 흐름이 어색한 부분이 없어야 한다.

**Why this priority**: 기능이 동작해도 움직임이 어색하면 완성도가 떨어진다. 핵심 기능(US1)과 전체 뷰(US2)가 갖춰진 뒤 다듬는 마감 작업이다.

**Independent Test**: 노드를 펼치고/접고/드래그하고/호버할 때 움직임이 부드럽게 이어지고, 갑작스러운 점프나 겹침 없이 안정적으로 자리잡는 것을 확인할 수 있다.

**Acceptance Scenarios**:

1. **Given** 그래프가 표시된 상태에서, **When** 노드를 펼치면, **Then** 자식 노드가 부드러운 스프링 모션으로 자연스럽게 자리잡고 갑작스러운 위치 점프가 없다.
2. **Given** 노드를 드래그할 때, **When** 포인터를 움직이면, **Then** 노드가 지연 없이 따라오고 연결된 노드들이 부드럽게 반응한다.
3. **Given** 노드에 마우스를 올렸을 때, **When** 하이라이트가 적용되면, **Then** 강조/흐림 전환이 부드럽게 이루어지고 깜빡임이 없다.
4. **Given** 여러 노드가 떠 있는 상태에서, **When** 시뮬레이션이 안정화되면, **Then** 노드들이 서로 겹치지 않고 읽기 좋은 간격으로 분포한다.

### Edge Cases

- 초기 전체 펼침 시 노드 수가 많아 패널을 벗어나는 경우 어떻게 처리하는가?
- 클릭으로 선택할 수 있는 활성 키워드 수에 상한이 있는가? 상한 초과 시 가장 오래된 선택을 밀어내는가?
- 노드 선택 상태와 펼침 상태가 별개인가? (펼쳤지만 기사 필터에는 넣지 않는 경우가 필요한가?)
- 기사 결과가 0건인 키워드를 선택하면 어떤 피드백을 주는가?
- 초기 펼침이 너무 많은 뉴스 요청을 유발하지 않도록 어떻게 제어하는가?

## Requirements *(mandatory)*

### Functional Requirements

- **FR-001**: 사용자가 연관 노드를 클릭해 선택하면, 해당 키워드가 즉시 기사 필터의 활성 키워드로 추가되어야 한다.
- **FR-002**: 선택된 키워드의 깊이(루트/자식/손자)와 무관하게 기사 결과에 반영되어야 한다 (루트 우선으로 잘려나가지 않음).
- **FR-003**: 활성 키워드 수에 상한이 있을 경우, 최근에 선택한 키워드를 우선하여 결과에 반영해야 한다.
- **FR-004**: 노드 선택을 해제하거나 노드를 접거나 제거하면, 해당 키워드가 활성 필터에서 제거되고 기사 결과가 갱신되어야 한다.
- **FR-005**: 첫 로드 시 그래프는 루트 키워드와 그 1차 연관 노드들이 이미 펼쳐진 전체 개요 상태로 표시되어야 한다.
- **FR-006**: 초기 펼침 상태에서도 노드의 펼치기/접기 토글이 정상 동작해야 한다.
- **FR-007**: 노드들은 한곳에 뭉치지 않고 패널 영역에 고르게 분포해야 한다 (겹침 최소화).
- **FR-008**: 노드 펼침/접힘은 부드러운 모션으로 전환되며 갑작스러운 위치 점프가 없어야 한다.
- **FR-009**: 드래그 시 노드가 포인터를 지연 없이 따라가고 연결 노드가 부드럽게 반응해야 한다.
- **FR-010**: 호버 하이라이트의 강조/흐림 전환이 부드럽고 깜빡임이 없어야 한다.
- **FR-011**: 초기 전체 펼침이 과도한 뉴스 요청을 유발하지 않도록 제어되어야 한다.
- **FR-012**: 현재 선택되어 기사 필터에 반영 중인 노드는 시각적으로 구분되어야 한다 (선택 상태 표시).

### Key Entities

- **활성 키워드 집합(Active Filter Set)**: 현재 기사 결과를 결정하는 키워드들. 속성: 키워드 id, 선택 순서/최근성, 깊이
- **노드 선택 상태(Node Selection)**: 각 그래프 노드가 기사 필터에 포함되어 있는지 여부. 속성: 노드 id, isSelected
- **그래프 초기 상태(Initial Graph State)**: 첫 로드 시 펼쳐질 노드 구성. 속성: 루트 키워드들, 펼칠 깊이(기본 1차)

## Success Criteria *(mandatory)*

### Measurable Outcomes

- **SC-001**: 사용자가 연관 노드를 클릭한 후 2초 이내에 해당 키워드 관련 기사가 결과 영역에 반영된다.
- **SC-002**: 선택한 노드의 깊이와 무관하게 100% 기사 결과에 반영된다 (루트만 반영되는 누락 0건).
- **SC-003**: 첫 로드 시 별도 조작 없이 루트 + 1차 연관 노드를 포함한 전체 구조가 화면에 표시된다.
- **SC-004**: 초기 표시 노드들이 패널 영역 내에서 서로 겹치지 않고 분포한다 (가시적 겹침 0건).
- **SC-005**: 펼침/접힘/드래그/호버 인터랙션이 끊김 없이(초당 약 60프레임 수준) 부드럽게 동작한다.
- **SC-006**: 사용자 테스트에서 80% 이상이 "인터랙션이 자연스럽다"고 평가한다.
- **SC-007**: 노드 선택 변경이 기존 기사 클러스터링/표시 기능과 회귀 없이 연동된다.

## Assumptions

- 이 작업은 기존 force-directed 그래프(feature 014)를 다듬는 개선이며 새로운 그래프를 만들지 않는다.
- "연관 노드 클릭"은 기존의 펼치기 동작과 결합되거나 별도의 선택 동작으로 해석할 수 있으며, 기본적으로 노드가 그래프에 표시(펼쳐짐)되면 기사 필터에도 포함되는 것으로 간주한다.
- 기사 결과 영역, 클러스터링, 뉴스 데이터 소스는 기존 것을 그대로 사용한다.
- 활성 키워드 상한은 뉴스 요청 품질을 위해 유지하되, 우선순위 기준을 "루트 우선"에서 "최근 선택 우선"으로 바꾸는 것이 핵심 수정이다.
- 초기 펼침 깊이는 1차(루트의 직접 자식)로 한다. 그 이상은 사용자가 클릭으로 확장한다.
- 데스크톱 우선이며 모바일 터치 최적화는 이번 범위 밖이다.
